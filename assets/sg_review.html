Security Group Review

Every inbound rule in one account set against the traffic its VPC flow logs actually carried, over time. Three timelines: who was refused (needs a rule, if wanted), how many allowed addresses were never seen (over-provisioned, and what to take away), and who was let in (with sources not seen in the last 24 hours apart, so DR tests, failovers and monthly batches stand out). Each source is named: this account or a range you call internal, a data centre, AWS (and which service), a SaaS provider, or the network by AS number.

1Refused sources

Distinct addresses turned away per period, by kind. A refused address needs a rule only if the traffic is wanted: internal and data centre sources usually are (a new service, a moved server), AWS and SaaS sometimes (health checks, webhooks, a partner's new egress), other networks rarely (scanners), so they are drawn in grey as the defences working, and in amber only in a period far above the usual level, which can mean a probe. Select a bar, or one colour in it, to list those sources; Extract rule then turns what is listed into the inbound rules that would let it in, with everything known about each source and port.

Rules that would let in the refused internal and data centre sources

Per security group and port, the refused private sources as the fewest exact ranges. Add them only if the traffic is wanted; sources a network ACL refused are left out (the ACL decides first).

2Over-provisioned addresses

For each security group with flow logs on all its interfaces, the addresses its rules let in that were never seen, summed over the groups, by kind. An address seen anywhere in the account in the whole read, let in or refused, is never counted. The rules in force at each time are worked back from today's through CloudTrail's record of rule changes (triangles: select one for the change). Rules open to every address (0.0.0.0/0) are listed below, not counted. The scale is logarithmic: each step down is a tenfold cut.

3Active sources

Distinct addresses let in per period. Dark: also let in during the last 24 hours. Light: not seen in the last 24 hours, the sources a rule change would hurt without warning (DR tests, failovers, month-end batches). Replies to the account's own outbound connections are left out. Select a bar to list its sources.

4Ports

Distinct sources per destination port over the timeline, coloured by what the port is for. Remote admin, database, Windows and directory, and container ports (marked ⚠) give control of a host or its data when reached: a refused internet source there is the rule doing its job; one let in deserves a look. Ports from 32768 up are read as one.
